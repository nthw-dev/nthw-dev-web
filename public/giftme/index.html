GiftMe แพลตฟอร์มรับโดเนทสำหรับสตรีมเมอร์

ระบบรับเงินสนับสนุนสำหรับสตรีมเมอร์ไทย ผู้ชมเปิดหน้าโดเนทสาธารณะของสตรีมเมอร์ จ่ายเงินด้วย PromptPay QR ผ่าน AQ1 Payment Gateway เมื่อชำระสำเร็จ ระบบจะยิงการแจ้งเตือนเข้า OBS browser source แบบเรียลไทม์ทันที พร้อมระบบยืนยันตัวตน (KYC) บัญชีธนาคาร สรุปยอดรายเดือน และแบ็กออฟฟิศสำหรับผู้ดูแล ประกอบด้วย 2 โปรเจกต์: API ภาษา TypeScript บน NestJS และเว็บ Next.js

สถาปัตยกรรมระบบ

เว็บไม่เรียก API ตรงจากเบราว์เซอร์ แต่วิ่งผ่านสายบังคับ 4 ชั้น: Server Action → Service singleton → BaseService.handleRequest → axios ทำให้ token และ BACKEND_API_URL อยู่ฝั่งเซิร์ฟเวอร์เสมอ · ฝั่ง API มี REST สำหรับแดชบอร์ดและ Socket.IO อีก 4 เส้นทางสำหรับ overlay ที่ยืนยันตัวตนด้วย token ไม่ใช่ JWT เพราะ OBS ส่ง header ไม่ได้

Backend · REST API + WebSocket (NestJS)

giftme-api — แกนกลางของระบบ

🔐การยืนยันตัวตนและสิทธิ์

  • JWT ออกโดย API ฝั่งเว็บเก็บไว้ใน cookie session แบบ httpOnly
  • payload ของ token ฝัง role พร้อมสถานะ KYC ทั้งสาม (verifyEmailStatus · verifyPhoneStatus · verifyBankAccountStatus) ทำให้กันสิทธิ์ได้โดยไม่ต้องยิงฐานข้อมูลซ้ำ — แต่ค่าจะเก่าจนกว่าจะออก token ใหม่
  • @UseGuards(JwtAuthGuard) ติดที่ระดับคลาสบ้างระดับเมธอดบ้าง ต้องดูทั้งสองจุดก่อนสรุปว่าเส้นไหนถูกป้องกัน
  • @GetUser() ดึง userId จาก token ให้เส้น profile/* ส่วน bo/* รับ userId มาทางพารามิเตอร์
  • Overlay token เส้น @Get(':token') เปิดสาธารณะโดยตั้งใจ เพราะ OBS ส่ง header ไม่ได้
  • 3 บทบาท: MEMBER ADMIN SUPER_ADMIN

🧱ข้อตกลงร่วมของโมดูล

  • ValidationPipe ระดับ global ตั้ง whitelist + forbidNonWhitelisted — ฟิลด์ที่ไม่มีใน DTO จะได้ 400 ทันที
  • ConfigModule เดียวโหลด config แบบ namespace (base · constant · database · aq1 · aws · email · streamlabs)
  • Joi schema เดียวบังคับ required() ทุกตัวแปร ตั้งค่าไม่ครบคือสตาร์ทไม่ขึ้น
  • URI versioning + global prefix api → ทุกเส้นเป็น /api/v1/...
  • โครงคู่ขนาน DTO ของ profile-* คือ bo-* ที่ตัด userId ออก · การเขียนฝั่ง self‑service เป็น @Post() แบบ upsert ไม่แยก create/update
  • Swagger ที่ /api-docs และเขียนไฟล์ public/swagger.json ใหม่ทุกครั้งที่บูต

🗄โมเดลข้อมูล (15 ตาราง)

  • Donation สร้างต่อเมื่อ payment สถานะ COMPLETED แล้วย้อน donationId กลับไปผูกกับ Payment

  • สถานะตรวจสอบ: DEFAULT · PENDING · APPROVED · REJECTED

🔗สายเรียก API 4 ชั้น

  • ①
    Server Actionsrc/actions/{user,backoffice}/*.action.ts ประกาศ "use server" · ฟอร์มที่เขียนข้อมูลตรวจ FormData ด้วย zod safeParse แล้วคืน field error ให้ useFormState
  • ②
    Service singletonsrc/services/** ทุกตัว extends BaseService และ export เป็นอินสแตนซ์เดียว เช่น profileService
  • ③
    handleRequestคืน ServiceResponse<T> = { data } หรือ { error } เสมอ ไม่เคย throw และเลือกข้อความจาก body ของ backend ก่อนข้อความของ axios
  • ④
    backendApi (axios)อินสแตนซ์เดียวใน src/lib/backend-api.ts ที่ interceptor แนบ Authorization: Bearer ให้อัตโนมัติ — client component ไม่เคยยิง API เอง
  • 🍪
    SessionJWT เก็บใน cookie session แบบ httpOnly · middleware.ts กัน /dashboard/* และ /backoffice/* โดยถอด token ที่ edge และบังคับบทบาท ADMIN/SUPER_ADMIN สำหรับแบ็กออฟฟิศ

Overlay — การแจ้งเตือนบนหน้าจอสตรีม

สิ่งที่ทำให้ GiftMe เป็นมากกว่าหน้าเก็บเงินคือ overlay สี่ตัวที่สตรีมเมอร์เอา URL ไปวางเป็น browser source ใน OBS แล้วการโดเนทที่ชำระสำเร็จจะเด้งขึ้นหน้าจอทันทีโดยไม่ต้องรีเฟรช ข้อจำกัดคือ OBS ส่ง header ไม่ได้ ระบบจึงใช้ token ในตัว URL เป็นตัวยืนยันตัวตน แทน JWT ทั้งฝั่ง REST และ WebSocket

4 widgetการยืนยันด้วย tokenหน้าตั้งค่าFlow การโดเนท

🔔widget ทั้งสี่

  • Alert การ์ดแจ้งเตือนรายครั้ง — สี ฟอนต์ รูป เวลาแสดง แอนิเมชันเข้า‑ออก (animate.css) เสียงแจ้งเตือน และเสียงอ่านข้อความ
  • Top Donator อันดับผู้โดเนทสูงสุด 3 คน นับตั้งแต่ startDateAt
  • Donate Latest รายการโดเนทล่าสุด
  • Donate Goal หลอดความคืบหน้าเทียบกับ amountGoal ในช่วงวันที่กำหนด
  • ทั้งสี่ตัวมีโครงเหมือนกันทุกชั้น (module ฝั่ง API · ตาราง setting · หน้าเว็บ · ฟอร์มตั้งค่า) การแก้ที่ตัวหนึ่งจึงมักต้องทำซ้ำอีกสามตัว

🔑token คือกุญแจ

  • ทุกแถว Overlay*Setting ถือ token สุ่มที่ unique และถูกฝังอยู่ใน URL ของ overlay
  • Socket.IO gateway (path: '/alert-gw' ฯลฯ, CORS *) ยืนยันตัวตนใน handleConnection ด้วยการหา handshake.query.token ในฐานข้อมูล ถ้าไม่พบจะ client.disconnect()
  • เก็บการเชื่อมต่อเป็น Map<token, Set<Socket>> จึงเปิดหลายหน้าต่างพร้อมกันได้
  • เส้น REST คู่กัน @Get(':token') เปิดสาธารณะโดยตั้งใจ อยู่ในคอนโทรลเลอร์เดียวกับเส้นที่ป้องกันด้วย JWT
  • PATCH reset-token ใช้หมุน token ใหม่เมื่อ URL หลุด — URL เดิมจะใช้ไม่ได้ทันที
  • ค่าตั้งไม่ได้ถูก seed ตอนสมัคร แต่ละ service จะเรียก createDefaultSetting() ด้วยค่าภาษาไทยที่ฮาร์ดโค้ดไว้ตอนเรียก getSetting() ครั้งแรก

🎛รายละเอียดที่ปรับได้

  • ยอดขั้นต่ำ แยกกันระหว่างการแสดงผล เสียงแจ้งเตือน และเสียงอ่านข้อความ
  • กรองคำหยาบ ทุก widget มี additionalBadWords ให้เติมคำเองนอกเหนือจากรายการพื้นฐาน
  • เสียงอ่านข้อความ ใช้ react-text-to-speech อ่านข้อความของผู้โดเนทออกลำโพง
  • แอนิเมชัน เลือกท่าเข้า‑ออกจาก animate.css พร้อมกำหนดระยะเวลาเป็นวินาที
  • ปุ่มทดสอบ POST /<name>-gw/test ยิงเหตุการณ์ปลอมเข้า overlay จากแดชบอร์ดได้โดยไม่ต้องโดเนทจริง

หน้าตกแต่งแจ้งเตือนโดเนท — ทั้งสี่แท็บ

การเชื่อมต่อระบบชำระเงิน

เงินทุกบาทวิ่งผ่าน AQ1 ทั้งขาเข้า (ผู้โดเนทสแกน PromptPay) และขาออก (โอนเข้าบัญชีสตรีมเมอร์) Aq1Service ห่อทุกเมธอดไว้ด้วย safeAxiosCall ที่คืนค่าเป็นทูเพิลสไตล์ Go คือ Promise<[Error | null, T | null]> ต่างจากส่วนอื่นของ API ที่โยน exception ของ Nest · เครื่องพัฒนาใช้ WireMock จำลอง gateway ทั้งชุดจึงทดสอบครบวงจรได้โดยไม่ต้องมี ngrok

🔌Gateway client

  • อยู่ที่ src/aq1/aq1.service.ts — ทุกเมธอดวิ่งผ่าน safeAxiosCall ตัวเดียว
  • Base URL ตั้งด้วย AQ1_BASE_URL · ยืนยันตัวตนด้วย AQ1_ACCESS_KEY + AQ1_SECRET_KEY
  • token ที่ได้จาก authenticate() ถูก cache ไว้ในหน่วยความจำตลอดอายุโปรเซส และไม่มีการต่ออายุ
  • ผู้เรียกต้องเช็กทั้ง error และ data.success เพราะ gateway ตอบ 200 พร้อมสถานะล้มเหลวได้

🧪WireMock stand-in

  • giftme_aq1_mock (พอร์ต 8090) จำลองทุก endpoint ที่ Aq1Service เรียก — หนึ่งไฟล์ mapping ต่อหนึ่งเส้น พร้อม body แบบ Handlebars ใน wiremock/__files/
  • เส้นที่ไม่ได้ map จะได้ 404 ที่ระบุ method และ path กลับมา ทำให้รู้ทันทีว่าลืม stub อะไร
  • .env.local.bk ตั้ง AQ1_BASE_URL="http://localhost:8090" ไว้ให้แล้ว
  • แก้ไฟล์ใต้ wiremock/ แล้วสั่ง npm run mock:aq1:reload พอ ไม่ต้องรีสตาร์ต container

↩️ตัวจำลอง webhook

  • giftme_aq1_callback ทำหน้าที่ยิง webhook ที่ WireMock ส่งเองไม่ได้ เพราะ extension ของมันเห็นแค่ originalRequest จึงอ่าน uuid ที่เพิ่งสุ่มให้ไม่ได้
  • worker จึงตาม request journal ของ WireMock (ซึ่งเก็บ response ที่เรนเดอร์แล้ว) และ POST callback สถานะ SUCCESS กลับเข้า API
  • หน่วงเวลา 10 วินาทีสำหรับ deposit และ 5 วินาทีสำหรับ withdraw
  • ตั้ง AQ1_MOCK_AUTO_CONFIRM=false เพื่อให้รายการค้างเป็น pending แล้วยิงเองด้วย npm run mock:aq1:webhook -- --status REJECTED

การพัฒนาและการ Deploy

ทั้งสองโปรเจกต์เป็น npm project อิสระ ไม่มี workspace ร่วม จึงต้อง npm i แยกกัน · ใช้ Node 20 และ run-script-os เพื่อให้สคริปต์ทำงานได้ทั้ง macOS/Linux และ Windows · เครื่องพัฒนายก PostgreSQL และ AQ1 mock ขึ้นด้วย docker compose แล้วรันแอปจาก source ส่วนการขึ้นระบบใช้ GitHub Actions สร้าง image แล้ว push ขึ้น Docker Hub

  • 🪣

▶ขั้นตอนรันระบบ

  1. nvm use 20 — ทั้งสองโปรเจกต์ล็อก Node 20.x
  2. cd giftme-api && npm i แล้ว npm run set:local — คัดลอก .env.local.bk เป็น .env
  3. npm run db:up — ยก postgres + AQ1 mock + callback worker
  4. npm run db:migrate แล้ว npm run db:seeds — สร้างตารางและข้อมูลตั้งต้น
  5. npm run dev — API ที่พอร์ต 3000
  6. cd giftme-web && npm i && npm run set:local && npm run dev — เว็บที่พอร์ต 8000

Swagger อยู่ที่ http://localhost:3000/api-docs · คำสั่งอื่นที่ใช้บ่อย: db:studio · db:generate · db:down · mock:aq1:logs · ฝั่งเว็บใช้ npm run check (lint + typecheck) เป็นประตูตรวจก่อนส่งงาน

🧩สถานะของชุดทดสอบ

  • Jest ถูกตั้งค่าไว้ใน giftme-api (testRegex: .*\.spec\.ts$ · rootDir src) แต่ ยังไม่มีไฟล์ .spec.ts อยู่เลย ทั้งสองโปรเจกต์ npm test จึงผ่านแบบว่างเปล่า
  • test:e2e ชี้ไปที่ ./test/jest-e2e.json ซึ่งยังไม่มีในทรี
  • giftme-web ยังไม่มี test runner — ด่านตรวจคือ next lint + tsc --noEmit
  • สเปกใหม่ควรวางใต้ giftme-api/src/** ให้ตรงรูปแบบ *.spec.ts

⚙CI/CD ของ API

  • สองไฟล์เวิร์กโฟลว์ที่โครงเหมือนกัน: dev.yml ทริกเกอร์จาก push เข้า dev และ main.yml จาก push เข้า main
  • ทั้งคู่ docker login ด้วย secret DOCKER_USER / DOCKER_PASSWORD แล้ว build จาก Dockerfile.backend
  • ติดแท็ก :latest อย่างเดียว ไม่มีแท็กตาม commit จึงย้อนเวอร์ชันจากรีจิสทรีไม่ได้
  • ไม่มีขั้นตอน lint / test / migrate ในไพป์ไลน์

⚙CI/CD ของเว็บ

  • dev.yml ทำงานเมื่อ push เข้า dev build จาก Dockerfile.frontend2 ขึ้นบัญชี iamta
  • main.yml ใช้ docker/build-push-action พร้อม QEMU + Buildx สำหรับ linux/amd64 ติดแท็กทั้ง :latest และ :<github.sha>
  • สายหลักของเว็บ push ขึ้น คนละบัญชี (enzoleroy) และใช้ คนละ Dockerfile กับสาย dev
  • main.yml ทริกเกอร์ด้วย pull_request ด้วย ทำให้ PR ทับแท็ก :latest ของ production ได้
