ระบบตัวกลางรับ‑จ่ายเงินสำหรับประเทศลาว ทำหน้าที่เชื่อมระบบของลูกค้าเข้ากับ payment gateway LaoITPGW / UniqPay ครอบคลุมการฝากเงินด้วย LaoQR การถอนเงินข้ามธนาคาร การรับ webhook ยืนยันผล และแดชบอร์ดสำหรับผู้ดูแลระบบ ประกอบด้วย 2 โปรเจกต์: API server ภาษา Go และเว็บแดชบอร์ด Next.js

Integration · LaoITPGW / UniqPay

การเชื่อมต่อ payment gateway

หัวใจของระบบคือการคุยกับ gateway ภายนอกอย่างปลอดภัยและตรวจสอบย้อนหลังได้ ทุกคำขอขาออกถูกเซ็นด้วย HTTP Message Signatures (RFC 9421) ทุก webhook ขาเข้าถูกตรวจลายเซ็นก่อนรับ และทุกครั้งที่สร้างรายการฝาก‑ถอนระบบจะเลือกบัญชีรับเงินที่โหลดน้อยที่สุดให้อัตโนมัติ

Gateway clientFlow ฝากเงินตัวเลือกบัญชีSQS

🔌Gateway client

  • อยู่ที่ adapter/laoitpgw — ทุกเมธอดวิ่งผ่านฟังก์ชันกลาง doRequest เดียว
  • Base URL ตั้งด้วย LAOIT_PGW_URL · timeout 30 วินาที
  • แปลง error ของ gateway เป็นชนิดของเราเอง (apiError / apiMsgError)
  • มีโหมด debug log สำหรับตรวจ request‑response จริง (HTTP_CLIENT_DEBUG_LOG)

🛡ความปลอดภัย

  • เซ็นขาออก ed25519 ตาม RFC 9421 ด้วย HTTPSIG_PRIVATE_KEY + KEY_ID + TAG
  • ตรวจขาเข้า webhook ต้องผ่าน HTTPSIG_VERIFY_PUBLIC_KEY ของ gateway ก่อนเข้าถึง handler
  • มีเครื่องมือ tools/keygen สร้างคู่กุญแจ (ed25519 / ecdsa-p256 / rsa-pss) สำหรับเครื่องพัฒนา
  • แยก binary ทำให้ endpoint webhook ไม่อยู่ในเซิร์ฟเวอร์เดียวกับ API ของแดชบอร์ด

📨Async / SQS

  • เมื่อธุรกรรมถึงสถานะปลายทาง ระบบ publish ข้อความเข้า SQS FIFO
  • จัดกลุ่มข้อความตามเลขบัญชี และกันข้อความซ้ำด้วย paymentRefId
  • ข้อความมี txnId · paymentRefId · status · method · amount · payee · payor
  • มี consumer ตัวอย่างที่ cmd/sqs และ producer ทดสอบที่ cmd/sqs/example_producer

Flow การฝากเงินด้วย LaoQR

แถวบนคือขาสร้างรายการ แถวล่างคือขายืนยันผลที่ gateway แจ้งกลับมา สถานะบนแดชบอร์ดเปลี่ยนเองจากการ polling ไม่ต้องรีเฟรชหน้า

ตัวเลือกบัญชีรับเงินอัตโนมัติ (Bank Account Selector)

ทุกครั้งที่สร้างรายการฝากหรือถอน ระบบต้องเลือกบัญชีที่รับยอดน้อยที่สุดของวันนั้น มีสองเส้นทางที่ให้ผลตรรกะเดียวกัน: เส้นทาง Redis เร็วและ atomic ส่วนเส้นทาง SQL เป็นตัวสำรอง สลับได้จากหน้าตั้งค่าโดยไม่ต้อง deploy ใหม่

เส้นทางปกติเส้นทางสำรองเมื่อ Redis ล้ม
ลำดับชั้นการปิด Redis — หยาบไปละเอียด
  • ระดับ deploy: ตั้ง REDIS_ENABLED=false — ไม่สร้าง client เลย
  • ระดับ boot: ping ไม่ผ่านตอนเริ่มระบบ — log เตือนแล้วไปใช้ SQL
  • ระดับ runtime: ปิดสวิตช์ bankSelectorRedisEnabled จากหน้าตั้งค่า — ไม่ต้อง deploy ใหม่
  • ทั้งสามระดับลงเอยที่เส้นทาง SQL เดียวกัน ผลลัพธ์เชิงตรรกะเหมือนกัน
  • ข้อควรรู้: สวิตช์มีแคช 30 วินาทีและแคชแยกตาม pod ช่วงสั้น ๆ หลังสลับอาจมี pod ที่ยังใช้เส้นทางเดิม · เมื่อเปิด Redis กลับหลังปิดไว้นาน ตัวนับอาจไม่ตรงและจะถูก warmup สร้างใหม่ให้เฉพาะวันที่ยังไม่เคย warm

การพัฒนาและการ Deploy

เครื่องพัฒนารัน dependency ทั้งหมดด้วย docker compose แยกไฟล์ต่อบริการ (PostgreSQL · Redis · LocalStack · WireMock) แล้วรัน Go จาก source ส่วนการขึ้นระบบใช้ GitHub Actions สร้าง image แล้ว push ขึ้น Amazon ECR

เครื่องพัฒนาDocker imageCI/CDตัวแปรสภาพแวดล้อม

🧰Dependency ฝั่งเครื่องพัฒนา

  • 🐘
    PostgreSQLimage postgres:latest · พอร์ต 5432 · ตั้ง timezone Asia/Bangkok ทั้ง container และ server
  • ⚡
    Redisimage redis:7-alpine · พอร์ต 6379 · เปิด appendonly และตั้งรหัสผ่าน
  • ☁️
    LocalStacklocalstack/localstack:3.8.1 · พอร์ต 4566 · จำลองเฉพาะ SQS
  • 🧪
    WireMockwiremock/wiremock:3.9.2 · พอร์ต 8081 · จำลอง LaoITPGW ตาม stub ใน deployments/wiremock/mappings

▶ขั้นตอนรันระบบ

  1. cp .env.example .env แล้ว direnv allow
  2. make up — เปิด dependency ทั้งหมดบน app-network
  3. make migrate-up แล้ว make seed — สร้างตารางและข้อมูลตั้งต้น
  4. go run cmd/api/main.go — Internal API ที่พอร์ต 8080
  5. go run cmd/laoitapi/main.go — ตัวรับ webhook
  6. bun dev ในโปรเจกต์เว็บ — แดชบอร์ดที่พอร์ต 4000

Swagger อยู่ที่ http://localhost:8080/swagger/index.html · สร้างคู่กุญแจสำหรับลายเซ็นด้วย go run ./tools/keygen -algo ed25519 -out ./keys

🧩ข้อมูลตั้งต้นจาก seed

  • สร้างผู้ใช้ ADMIN และ service account บทบาท API
  • API token ของ service account เก็บเป็นค่าแฮชพร้อม pepper — ต้องตรงกับที่ middleware คำนวณ
  • สร้างคู่ธุรกรรม‑รายการฝากตัวอย่างพร้อม payload QR แบบ EMVCo
  • รันบน staging ได้ผ่าน scripts/docker-db.sh migrate-up และ scripts/docker-db.sh seed

⚙CI/CD ของ API

  • ทริกเกอร์: push ขึ้น main · สร้าง tag · pull request · เรียกมือ
  • ci.yaml รันเป็น matrix 4 service เรียก workflow กลาง build-and-push.yml
  • ยืนยันตัวตนกับ AWS ด้วย OIDC (ไม่มี access key ค้างใน repo)
  • Push ขึ้น ECR ภูมิภาค ap-southeast-1
  • Tag: stable-<sha7> เมื่อมาจาก main · nightly-<sha7> กรณีอื่น · พร้อมอัปเดต latest

⚙CI/CD ของเว็บ

  • build.yml ทำงานเมื่อ push หรือ PR เข้า main
  • เรียก workflow ที่แชร์ไว้ภายนอก Zap1Lab/aws-app-helm
  • Push ขึ้น ECR repo tx-service-laos-frontend ด้วย prefix nightly- แพลตฟอร์ม linux/amd64
  • ส่ง GIT_SHA เข้าไปเป็น build arg
  • retag.yml ทำงานเมื่อสร้าง git tag เพื่อเปลี่ยน image เดิมให้เป็นเวอร์ชันที่ตั้งชื่อไว้
  • มี dev.yml สำหรับ branch develop ที่ push ขึ้น Docker Hub แยกจากสาย ECR
ข้อสังเกตที่ควรตรวจก่อนขึ้นระบบจริง
  • มีสาย build ทับซ้อนกันสามชุด (ci.yaml → ECR, build.yml → workflow ภายนอก, dev.yml → Docker Hub) ควรกำหนดให้ชัดว่า environment ไหนใช้สายไหน
  • scripts/docker-db.sh ยังมีค่ารหัสผ่านตัวอย่างค้างอยู่ ต้องเปลี่ยนก่อนใช้กับฐานข้อมูลจริง

ตัวแปรสภาพแวดล้อมที่สำคัญ

ค่าที่ทำเครื่องหมาย “จำเป็น” ถ้าไม่ตั้ง ระบบจะไม่สตาร์ท
ตัวแปรโปรเจกต์จำเป็นคำอธิบาย
NAME · PORT · CORSAPIPORT · CORSชื่อเซอร์วิสที่ใช้เป็นส่วนหนึ่งของ path · พอร์ต · รายการ origin ที่อนุญาต
ENV · LOG_LEVELAPI—LOCAL / DEV / UAT / PROD · ระดับ log
DATABASE_URLAPIจำเป็นสตริงเชื่อม PostgreSQL
HASH_PEPPER · JWT_SECRETAPIจำเป็นpepper สำหรับแฮช API token และ secret ของ JWT
JWT_DURATIONAPI—อายุ token ค่าเริ่มต้น 24h
SERVICE_NAME_IDAPIจำเป็นรหัสเซอร์วิส ใช้เป็น namespace ของ key ใน Redis
LAOIT_PGW_URLAPIจำเป็นปลายทางของ gateway (ชี้ไป WireMock ตอนพัฒนา)
HTTPSIG_KEY_ID · ALGORITHM · TAG · PRIVATE_KEYAPIจำเป็นกุญแจและพารามิเตอร์สำหรับเซ็นคำขอขาออก
HTTPSIG_VERIFY_KEY_ID · TAG · PUBLIC_KEYAPIจำเป็นกุญแจสาธารณะของ gateway สำหรับตรวจ webhook
AWS_REGION · SQS_QUEUE_URLAPIจำเป็นภูมิภาคและคิว SQS ปลายทาง
SQS_LOCALSTACK_ENABLEDAPI—ถ้า true จะข้ามการตรวจสิทธิ์เข้าถึงคิวตอนสตาร์ท
REDIS_ENABLED · ADDRS · PASSWORD · DB · TLS_ENABLED · DIAL_TIMEOUTAPI—ค่าเชื่อม Redis · ถ้าปิดหรือ ping ไม่ผ่าน ตัวเลือกบัญชีจะใช้ SQL
ENABLE_SWAGGER_DOCS · SWAGGER_*API—เปิดหน้า Swagger และค่าที่แสดงในเอกสาร
DEVMODE_ENABLED · DEVMODE_AUTO_WEBHOOK_*API—โหมดพัฒนา ยิง webhook กลับเข้าตัวเองเพื่อทดสอบ ไม่ควรเปิดบน production
API_BASE_URLWebจำเป็นปลายทาง API — เป็นตัวแปรฝั่งเซิร์ฟเวอร์เท่านั้น ไม่มี NEXT_PUBLIC_
ENABLE_API_LOGGING · NEXT_PUBLIC_ENABLE_API_LOGGINGWeb—เปิด log การเรียก API ฝั่งเซิร์ฟเวอร์และฝั่ง client
NEXT_PUBLIC_SHOW_DEMO_CREDENTIALSWeb—แสดงปุ่มเติมบัญชีทดลองบนหน้าเข้าสู่ระบบ ควรปิดบน production
SKIP_ENV_VALIDATIONWeb—ข้ามการตรวจ env ใช้เฉพาะตอน build image
