Deploy · UAT

hr_mobile / browser → Cloudflare edge → Tunnel → cloudflared → hr-bo / hr-api → postgres

ทุกอย่างอยู่ใน docker compose ชุดเดียวบน EC2 t4g.small: cloudflared, hr-bo, hr-api และ postgres ไม่มี container ไหน publish port ออก host ยกเว้น postgres ที่ผูก loopback ไว้ให้ SSM port-forward · hr_mobile build UAT ชี้ BASE_URL มาที่โดเมน API ของ UAT

🧭ขั้นตอนสร้าง (3 ขั้น · ~6 นาที)

  1. ./create_host.sh VPC + IAM + SG(ว่าง) + EC2 + Docker 3–4 นาที
  2. ./create_tunnel.sh Tunnel + ingress 2 hostname + CNAME < 1 นาที
  3. ./deploy.sh ส่ง compose.yaml ผ่าน SSM → เขียน .env → migrate → compose up -d → รอ 200 1–2 นาที

ขั้น 3 คือคำสั่งที่รันซ้ำตลอดอายุของ environment: APP_TAG=<tag> ./deploy.sh (GitHub Actions เรียกให้อัตโนมัติ ดูหัวข้อ CI/CD) · ตรวจสอบ ./verify.sh · ลบทิ้ง ./destroy.sh --yes (~2 นาที)

compose.yaml บนเครื่อง UAT (/opt/northhr)

name: northhr
services:
  cloudflared:
    image: cloudflare/cloudflared:latest
    command: tunnel --no-autoupdate --metrics 0.0.0.0:2000 run
    environment: { TUNNEL_TOKEN: "${TUNNEL_TOKEN}" }
    depends_on: [bo, api]
    restart: always

  bo:                                  # hr-bo · Next.js standalone
    image: "${BO_IMAGE}:${APP_TAG}"    # Docker Hub · arm64
    environment:
      BACKEND_API_URL: http://api:3000
      NEXT_PUBLIC_GOOGLE_MAPS_API_KEY: "${GOOGLE_MAPS_API_KEY}"
    restart: always

  api:                                 # hr-api · NestJS
    image: "${API_IMAGE}:${APP_TAG}"   # Docker Hub · arm64
    env_file: api.env                  # POSTGRES_PRISMA_URL JWT_* AWS_* SMTP_* CORS_*
    environment: { PORT: "3000" }
    depends_on:
      db: { condition: service_healthy }
    restart: always

  db:
    image: postgres:16
    environment:
      POSTGRES_DB: "${DB_NAME}"
      POSTGRES_USER: "${DB_USER}"
      POSTGRES_PASSWORD: "${DB_PASSWORD}"
    volumes: [pgdata:/var/lib/postgresql/data]
    ports: ["127.0.0.1:5432:5432"]     # loopback เท่านั้น
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U ${DB_USER} -d ${DB_NAME}"]
      interval: 5s
      timeout: 3s
      retries: 12
    restart: always

volumes:
  pgdata: {}

k3s บน EC2 หลายเครื่องคนละ AZ รัน pod ของ hr-bo และ hr-api พร้อม HPA · ฐานข้อมูลเป็น RDS PostgreSQL Multi-AZ · ขาเข้ายังเป็น Cloudflare Tunnel เหมือน UAT จึงไม่มี ALB, ACM, NAT และไม่มี inbound 80/443

สถาปัตยกรรม PROD (ผู้ใช้ 3,000–4,000 คน)

โหลดของระบบ HR เป็นช่วงสั้น ๆ: check-in เช้าและ check-out เย็นราว 30 นาที ถ้าพนักงาน 4,000 คนลงเวลาในช่วงนั้นจะได้เฉลี่ยราว 2–3 request/วินาที และ burst หลักสิบ request/วินาที ซึ่ง hr-api 2–6 pod บน 3 node รับได้สบาย จุดที่ต้องระวังคือฐานข้อมูลและ connection pool จึงยกไป RDS

request จากผู้ใช้cloudflared ต่อออกหา Cloudflareผู้ดูแลผ่าน SSM / kubectlเรียกบริการภายนอก
จุดออกแบบสำคัญของ PROD
  • Deployment bo และ api แยกกัน คนละ Service, คนละ HPA, และมี PodDisruptionBudget minAvailable: 1 ให้ patch node ทีละเครื่องได้โดยไม่ล่ม
  • 3 node คนละ AZ (./add_node.sh 2) · topologySpreadConstraints ให้ pod ของ api/bo และ cloudflared กระจายทุก node · cloudflared 3 replica = 3 connector ของ tunnel เดียว Cloudflare กระจายโหลดให้เอง
  • RDS db.t4g.small Multi-AZ เปิด automated backup 7 วัน + deletion protection · hr-api ต่อผ่าน POSTGRES_PRISMA_URL ที่ประกอบจาก secret rds-credentials (ตั้ง connection_limit ต่อ pod ให้รวมไม่เกิน max_connections ของ RDS)
  • ทุก release รัน Job prisma migrate deploy ด้วย image hr-api ตัวเดียวกัน แล้ว kubectl wait --for=condition=complete ก่อน rollout · migration เขียนแบบ backward-compatible (expand → migrate → contract) เพราะ pod เก่าและใหม่รันพร้อมกันระหว่าง rolling update
  • Cloudflare ฝั่ง PROD เปิด WAF managed rules, rate limit ที่ /api/v1/auth/* และ Bot Fight Mode · เปิด Cloudflare Access เฉพาะโดเมน back-office ถ้าต้องการจำกัดให้ HR ที่มีอีเมลองค์กร

☸Workload บน k3s

  • hr-api Deployment 2 replica · HPA 2→6 ที่ CPU 60% · requests 250m/256Mi · readiness ที่ /api/v1/health · PDB minAvailable 1
  • hr-bo Deployment 2 replica · HPA 2→4 · requests 150m/256Mi · BACKEND_API_URL=http://api:3000 (ภายใน cluster ไม่ออก Cloudflare)
  • cloudflared Deployment 3 replica · anti-affinity ต่อ node · liveness /ready :2000 · token จาก secret cloudflared-token
  • migrate Job ต่อ release · backoffLimit: 0 · ถ้า fail จะไม่ rollout ต่อ
  • Secret rds-credentials (สร้างตอนสร้าง RDS) และ app-secrets (JWT, S3, SMTP, Maps) apply จากไฟล์นอก git · ขั้นถัดไปคือดึงจาก AWS Secrets Manager ผ่าน External Secrets
  • ไม่มี Ingress controller routing อยู่ที่ ingress ของ tunnel ฝั่ง Cloudflare: hr.nthw.dev → http://bo.default.svc:3000 และ api.hr.nthw.dev → http://api.default.svc:3000

🧭ขั้นตอนสร้าง (5 ขั้น · ~20 นาที)

  1. ./create_node.sh VPC + IAM + EIP + EC2 server + k3s + kubeconfig 5 นาที
  2. ./create_rds.sh subnet group + SG + RDS Multi-AZ + secret rds-credentials 10–12 นาที
  3. ./create_tunnel.sh Tunnel + ingress 2 hostname + CNAME + secret token < 1 นาที
  4. ./add_node.sh 2 agent 2 เครื่องคนละ AZ join cluster 3 นาที
  5. ./deploy.sh apply secrets → Job migrate → api/bo/cloudflared + HPA → รอ 200 1–2 นาที

Pipeline

เส้นน้ำเงิน = ขั้นใน pipeline · ทุก push ขึ้น main ไป UAT อัตโนมัติ · tag v* ไป PROD หลังผู้ดูแลกดอนุมัติใน GitHub Environment production

ขั้นใน pipelineเครื่องปลายทาง pull image จาก Docker Hub

🏗Build → Docker Hub

  • Trigger push ไป main ของ hr-api หรือ hr-bo → tag <date>-<sha> · git tag v* → tag เวอร์ชัน · ทั้งคู่ push latest ด้วย
  • Buildx --platform linux/arm64 ให้ตรง t4g · cache layer ใน GHA · Dockerfile หลายขั้นของแต่ละโปรเจกต์
  • Scan Trivy ตรวจ image ก่อน push · fail เมื่อพบ CRITICAL
  • Secret DOCKERHUB_USERNAME + DOCKERHUB_TOKEN (access token สิทธิ์ write เฉพาะ repo northhr/*)

🧪Update container บน UAT (อัตโนมัติ)

  • เมื่อ job build จาก main ผ่าน
  • สิทธิ์ role OIDC ให้ ssm:SendCommand เฉพาะ instance ที่ tag env=uat
  • คำสั่งบนเครื่อง เขียน APP_TAG ลง .env → docker compose pull → compose run --rm api npx prisma migrate deploy → compose up -d (recreate เฉพาะ service ที่ image เปลี่ยน DB ไม่ถูกแตะ)
  • ตรวจ job รอ https://api.uat.nthw.dev/api/v1/health = 200 · fail = job แดง ให้ rerun ด้วย tag ก่อนหน้า

🚀Update pod บน PROD (กดอนุมัติ)

  • เมื่อ tag v* และผ่าน UAT แล้ว · GitHub Environment production ต้องมี reviewer กดอนุมัติก่อน job รัน
  • สิทธิ์ role OIDC ให้ ssm:SendCommand ที่ server k3s (tag env=prod) · kubectl รันบนเครื่องผ่าน SSM ไม่ต้องเปิด 6443 ให้ runner
  • คำสั่งบนเครื่อง snapshot RDS → Job prisma migrate deploy → kubectl set image deploy/api deploy/bo → rollout status · pod เก่าถูกแทนทีละตัว ผู้ใช้ไม่เห็น downtime
  • rollback kubectl rollout undo หรือ rerun job ด้วย tag ก่อนหน้า · DB กลับด้วย snapshot ก่อน migrate

.github/workflows/deploy.yml ของ hr-api (hr-bo เหมือนกัน เปลี่ยนชื่อ image)

name: build-and-deploy
on:
  push:
    branches: [main]
    tags: ['v*']

permissions: { id-token: write, contents: read }

jobs:
  build:
    runs-on: ubuntu-latest
    outputs: { tag: ${{ steps.meta.outputs.tag }} }
    steps:
      - uses: actions/checkout@v4
      - id: meta
        run: |
          if [[ "$GITHUB_REF" == refs/tags/* ]]; then echo "tag=${GITHUB_REF#refs/tags/}" >> $GITHUB_OUTPUT
          else echo "tag=$(date +%Y.%m.%d)-${GITHUB_SHA::7}" >> $GITHUB_OUTPUT; fi
      - uses: docker/setup-qemu-action@v3
      - uses: docker/setup-buildx-action@v3
      - uses: docker/login-action@v3
        with: { username: ${{ secrets.DOCKERHUB_USERNAME }}, password: ${{ secrets.DOCKERHUB_TOKEN }} }
      - uses: docker/build-push-action@v6
        with:
          platforms: linux/arm64
          push: true
          tags: |
            northhr/hr-api:${{ steps.meta.outputs.tag }}
            northhr/hr-api:latest
          cache-from: type=gha
          cache-to: type=gha,mode=max

  deploy-uat:
    needs: build
    if: github.ref == 'refs/heads/main'
    runs-on: ubuntu-latest
    steps:
      - uses: aws-actions/configure-aws-credentials@v4
        with: { role-to-assume: ${{ vars.AWS_DEPLOY_ROLE }}, aws-region: ap-southeast-1 }
      - run: |
          aws ssm send-command --targets Key=tag:env,Values=uat \
            --document-name AWS-RunShellScript \
            --parameters commands="cd /opt/northhr && APP_TAG=${{ needs.build.outputs.tag }} ./update.sh" \
            --cloud-watch-output-config CloudWatchOutputEnabled=true

  deploy-prod:
    needs: build
    if: startsWith(github.ref, 'refs/tags/v')
    environment: production          # reviewer กดอนุมัติที่นี่
    runs-on: ubuntu-latest
    steps:
      - uses: aws-actions/configure-aws-credentials@v4
        with: { role-to-assume: ${{ vars.AWS_DEPLOY_ROLE }}, aws-region: ap-southeast-1 }
      - run: |
          aws ssm send-command --targets Key=tag:env,Values=prod-server \
            --document-name AWS-RunShellScript \
            --parameters commands="cd /opt/northhr && APP_TAG=${{ needs.build.outputs.tag }} ./update.sh"
